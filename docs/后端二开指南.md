# 后端二开指南

> 目标：让开发者 / AI 以**最短路径**新增一个业务模块。请先读 [项目结构与设计亮点.md](./项目结构与设计亮点.md) 建立心智模型，再照本文的「7 步流程 + 四件套模板」落地。
> 所有范本优先照抄 `backend/src/system/user/`（用户模块四件套）。

---

## 一、新增业务模块的标准 7 步

> 二开业务统一放 `backend/src/business/<模块>/`，**不要**放进 `system/` 或 `support/` 底座。

1. **建迁移**：在 `backend/migrations/business/` 新建 `V0020__create_<表>.up.sql` / `.down.sql`（号段从 **`V0020`** 起，4 位补零）。建表文件采用「建表 → `COMMENT ON` → 索引」三段式，索引不单独占版本。
2. **写模型** `model.rs`：用 `#[derive(Model)]` + `#[table("your_table")]` 声明实体；需要自写 SQL / 领域逻辑的函数集中放这里。
3. **写 DTO** `dto.rs`：请求 `*Req`（带 `validator::Validate`）、响应 `*Res`（带 `from_model` 构造器，可空文本列统一降级为空串）。
4. **写处理器** `handler.rs`：用 `#[alun::permission(path, method, permission)]` + `#[alun::get/post/...]` 声明路由；参数校验与响应组装在 handler，SQL 下沉到 model。
5. **声明模块** `mod.rs`：写模块文档（含接口一览表），`pub mod dto; pub mod handler; pub mod model;`。
6. **挂菜单种子**：在 `backend/migrations/seed/` 追加菜单与按钮权限点，`module_code = 'business'`，用 `ON CONFLICT ... WHERE deleted_at IS NULL` 幂等。
7. **编译验证**：`cargo fmt && cargo clippy -- -D warnings && cargo check`；`cargo run` 自动迁移并启动。

> 权限码三段式 `{模块}:{资源}:{动作}`（如 `business:article:create`），必须与 `sys_menu.auth_code` 和 `#[alun::permission(...)]` 三处一致。

## 二、四件套模板（可照抄）

### 2.1 `mod.rs`（模块文档 + 声明）
```rust
//! 文章管理子模块。
//!
//! | 文件 | 内容 |
//! |------|------|
//! | [`model`] | [`model::ArticleModel`]（`biz_article`） |
//! | [`dto`] | 列表 / 详情 / 增改请求与响应 |
//! | [`handler`] | 分页、详情、增删改 |
//!
//! 对外路径前缀 `/api/business/article`。

pub mod dto;
pub mod handler;
pub mod model;
```

### 2.2 `model.rs`（实体 + 数据访问）
```rust
use alun::prelude::*;
use crate::utils;

#[derive(Debug, Clone, Model)]
#[table("biz_article")]
pub struct ArticleModel {
    pub id: uuid::Uuid,
    pub title: String,
    pub content: Option<String>,
    pub status: crate::shared::constants::EnableStatus,
    pub created_at: chrono::DateTime<chrono::Utc>,
    pub updated_at: chrono::DateTime<chrono::Utc>,
    pub deleted_at: Option<chrono::DateTime<chrono::Utc>>,
}

// 需要自写 SQL / 领域逻辑的函数集中在此（仅调用框架快捷方法时可在 handler 直接写）。
pub(crate) async fn page_articles(
    filter: &ArticleFilter, page: u64, page_size: u64,
) -> DbResult<PageData<Vec<ArticleModel>>> {
    let rows = ArticleModel::query()
        // #if / #and 自动参数化，绝不做字符串拼接
        #if let Some(kw) = &filter.keyword {
            .sql(#and "title ILIKE #{kw}")   // kw 已在 handler 拼成 %kw%
        }
        .paginate(page, page_size)
        .await?;
    Ok(rows)
}
```

### 2.3 `dto.rs`（请求 / 响应）
```rust
use alun::prelude::*;
use serde::{Deserialize, Serialize};
use validator::Validate;
use crate::business::article::model::ArticleModel;

#[derive(Debug, Clone, Serialize)]
pub struct ArticleRes {
    pub id: String,
    pub title: String,
    pub content: String,            // 可空文本列统一降级为空串
    pub status: i16,
    pub created_at: chrono::DateTime<chrono::Utc>,
}
impl ArticleRes {
    pub fn from_model(m: &ArticleModel) -> Self {
        Self {
            id: m.id.to_string(),
            title: m.title.clone(),
            content: m.content.clone().unwrap_or_default(),
            status: m.status.as_i16(),
            created_at: m.created_at,
        }
    }
}

#[derive(Debug, Clone, Deserialize, Validate)]
pub struct ArticleCreateReq {
    #[validate(length(min = 1, max = 120))]
    pub title: String,
    pub content: Option<String>,
}
```

### 2.4 `handler.rs`（路由 + 编排）
```rust
use alun::prelude::*;
use axum::http::HeaderMap;
use std::net::SocketAddr;
use crate::shared::constants::EnableStatus;
use crate::business::article::dto::{ArticleCreateReq, ArticleRes};
use crate::business::article::model::{self, ArticleModel};
use crate::utils;

#[alun::permission(path = "/business/article/page", method = "GET", permission = "business:article:list")]
#[alun::get("/business/article/page")]
pub async fn page(Query(query): Query<ArticlePageQuery>) -> ResResult<PageData<Vec<ArticleRes>>> {
    let (page, page_size) = utils::normalize_page(query.page, query.page_size);
    let filter = model::ArticleFilter { keyword: query.keyword.map(|k| format!("%{k}%")) };
    let page_data = model::page_articles(&filter, page, page_size)
        .await
        .map_err(|e| utils::db_error(e, "分页查询文章"))?;
    let list = page_data.list.iter().map(ArticleRes::from_model).collect();
    Ok(Res::page(list, page_data.total, page_data.page, page_data.size))
}

#[alun::permission(path = "/business/article", method = "POST", permission = "business:article:create")]
#[alun::post("/business/article")]
pub async fn create(
    headers: HeaderMap,
    ConnectInfo(_conn): ConnectInfo<SocketAddr>,
    Extension(AuthClaims(claims)): Extension<AuthClaims>,
    ValidatedJson(req): ValidatedJson<ArticleCreateReq>,
) -> ResResult<ArticleRes> {
    let mut m = ArticleModel {
        id: uuid::Uuid::now_v7(),
        title: req.title.trim().to_string(),
        content: req.content.map(|v| v.trim().to_string()),
        status: EnableStatus::enabled,
        created_at: chrono::Utc::now(),
        updated_at: chrono::Utc::now(),
        deleted_at: None,
    };
    m.insert().await.map_err(|e| utils::db_error(e, "新建文章"))?;
    Ok(Res::ok(ArticleRes::from_model(&m)))
}
```

## 三、路由与权限

- **宏声明**：`#[alun::get("/business/article/page")]`；路径**不含** `/api` 前缀（由 `[router] prefix` 注入）。
- **权限**：`#[alun::permission(path, method, permission)]`；`SUPER_ADMIN` 以 `role_code == 'SUPER_ADMIN'` 短路全部校验。
- **免鉴权**：用 `#[alun::no_auth("/path")]`；`/health` 在 `lib.rs` 里手动 `.get()` 注册豁免前缀。
- **常用提取器**：`Query<T>`、`Path<String>`、`ValidatedJson<T>`、`Extension(AuthClaims)`、`ConnectInfo<SocketAddr>`、`HeaderMap`。

## 四、错误处理（出口只有三个名字）

| 位置 | 返回类型 | 说明 |
|------|----------|------|
| handler | `ResResult<T>` | 业务处理器；`Ok(Res::ok(x))` / `Ok(Res::page(...))` |
| model | `DbResult<T>` | 数据访问层 |
| 启动 / 插件 / 任务 | `alun::Result<T>` | 框架级 |

**铁律**：handler 内 `DbError / io::Error / alun_core::Error` 直接 `?` 传播：
```rust
let user = load_user(&id).await?;                       // 自定义辅助返回 ResResult
let rows = model::page_x(&f, p, s).await
    .map_err(|e| utils::db_error(e, "分页查询X"))?;      // 仅在需补充中文上下文时包一层
```
**不要**写多余的 `.map_err(ApiError::internal(...))`；**禁止** `unwrap()` / `expect()`（clippy `-D warnings` 会拦）。

## 五、事务（RAII 闭包，自动回滚）

```rust
use alun::prelude::*;
db().transaction(|tx| async move {
    // tx 是 &Transaction，Model API 同样可用：model::do_a(&tx).await?;
    // 返回 Err 自动回滚；绝不让未提交事务的连接归还连接池
    Ok(())
}).await?;
```
首参统一 `&impl SqlExecutor`：`&Db` 与 `&Transaction` 通用。

## 七、鉴权上下文与当前用户

- 在 handler 签名加 `Extension(AuthClaims(claims)): Extension<AuthClaims>`，`claims.username` / `claims.user_id` 可取当前操作人。
- 写审计字段用 `claims.user_id` 填 `create_by / update_by`。

## 八、feature 开启（能力点单）

默认集是 `core`（非 `full`）。用到什么能力就在 `backend/Cargo.toml` 的 `features = [...]` 加：
- 数据库驱动：`postgres` / `mysql` / `sqlite`（`db` 仅表能力、不含驱动）。
- 预设 `mini ⊂ lite ⊂ full`；常用 `lite`（= core+postgres+cache+plugin+fs-local）。
- 点单：`fs-local`/`fs-minio`（文件）、`xlsx`、`sse`、`metrics`、`template`、`xss`。
> **依旧只声明 `alun` 一个 crate**，绝不引入 `alun-db` 等子 crate。

## 九、迁移编写细则

- 文件名 `V{n}__{Name}.up.sql` / `.down.sql`（成对）；种子 `S__{Name}.sql`。
- **已应用迁移指纹校验不可改**：演进只加新版本，不要回改历史迁移。
- 建表文件三段式：建表 → `COMMENT ON TABLE/COLUMN` → 索引（索引随表一起删，down 无需单独 `DROP INDEX`）。
- 种子 `ON CONFLICT ... WHERE deleted_at IS NULL DO NOTHING` 幂等；菜单/权限点属纯数据，一律追加种子 SQL，**不写 Rust**。
- 二开业务迁移号段 `V0020+`，与 `src/business/` 对应。
