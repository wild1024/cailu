# 配色方案（8 套色板 × 明暗双模式，默认不应用）

> 面向二次开发者：读完这份文档你应该能「换掉某一套色值」「新增一套方案」「排查配色不生效」，并且知道本项目配色的对比度底线在哪。

## 一、它是什么

管理后台的**用户自选配色方案**功能：8 套色板 × 浅色/深色 = **16 组配色**，用户在外观设置页或顶栏快捷面板点一下即生效（无需刷新、无需保存），选择记在浏览器本地。

**默认不应用任何方案**（这是本功能的定位，不是可选项）：

| 用户行为 | 界面表现 | `<html>` 上的注入 |
|---|---|---|
| 首次访问 / 清空 localStorage / 点「跟随默认」 | 与升级前**完全一致**（`theme.less` 原有青蓝色系） | 无任何内联变量、无 `data-palette*` 属性 |
| 主动点选某套方案 | 该套方案即时生效 | 内联 style 注入整张变量表 + `data-palette` / `data-palette-mode` |
| 已选方案后点「跟随默认」 | 立刻回到原主题 | 内联变量与属性全部移除，localStorage 键删除 |

关键设计：**没有 8 份 theme.less**。每套方案只声明 **5 个基准色**，其余上百个 CSS 变量（品牌色阶 1~10、容器色、描边、文字、图表色、阴影、渐变）全部在运行时推导，写进 `<html>` 的内联 style。现有组件（含 TDesign）**零改动**即换肤。

| 文件 | 作用 |
|---|---|
| `frontend/src/style/palettes.ts` | 色板定义 + 颜色运算 + 色阶推导 + 变量生成 + 对比度检查（纯函数，无 DOM/Vue 依赖） |
| `frontend/src/composables/usePalette.ts` | 把变量写到 `<html>`、localStorage 持久化、与明暗模式联动 |
| `frontend/src/views/user/preference.vue` | 外观设置页（跟随默认 + 8 套色卡 + 明暗切换 + 实时预览 + 16 组对比度报告） |
| `frontend/src/layouts/components/PaletteSwitch.vue` | 顶栏快捷切换（图标按钮 + 下拉面板，首项为「跟随默认」） |
| `frontend/src/style/palette-bridge.less` | 桥接层：把「主色上的文字」接到推导出的 token 上（只改颜色，不改组件结构；**全部带 fallback**，未选方案时不生效） |
| `frontend/scripts/check-palettes.mjs` | 检查脚本：色值自检 + 色阶断言 + 16 组对比度报告 + 「默认必须为 null」断言（`pnpm check:palettes`） |

## 三、色阶推导算法

### 3.1 亮色模式：`brandScaleLight(brand, brandLight)`

两个锚点：**brand-5 = 色板给定的浅色（原值不动）**、**brand-7 = 色板主色（原值不动）**，其余等级按 HSL 明度阶梯插值：

```
L(brand-1..4) = 96, 92, 87, 80          // 近白的浅底/悬停底
L(brand-5)    = 给定浅色的 L（钳制到 [55,82] 且必须 > 主色 L + 6）
L(brand-6)    = (L5 + L7) / 2            // 悬停档，落在浅色与主色中间
L(brand-7)    = 主色 L
L(brand-8..10)= L7 - 9, L7 - 18, L7 - 27 // active / 强调 / 最深
```

- **色相全程锁定主色色相**（不漂移，观感统一）；
- 饱和度：1~3 级乘 0.72、4 级乘 0.86、其余取主色饱和度（避免近白色发脏）；
- 色阶单调性由脚本断言（1 最浅 → 10 最深）。

### 3.2 深色模式：`brandScaleDark(brand, pageBg)`

与 TDesign 深色语义一致：**1 级最深（选中底）、7 级主色、8~10 级比主色更亮**。

```
L7 = clamp(主色 L + 14, 44, 62)          // 提亮：深底上原色会糊
若 contrast(L7, 深色页面底) < 3.0 则继续 +1 提亮（上限 78）
L1..6  = L7 - 32, -27, -22, -17, -12, -6
L8..10 = L7 + 7, +14, +21
```

### 3.3 中性色与文字色

| 变量组 | 亮色模式 | 深色模式 |
|---|---|---|
| `--td-bg-color-page` | 交融色原值 | 交融色压暗到 L=11%（保留色相，饱和度上调一点） |
| `--td-bg-color-container` | 交融色 → 白 62% | 交融色 → L=16% |
| `--td-bg-color-secondarycontainer` / `-component` | 容器色 → 交融色 34% / 20% | L=21% / 24% |
| `--td-component-stroke` | 渐染色 → 容器 42% | L=26%（比底亮一档才看得见） |
| `--td-component-border` | 渐染色**原值** | 渐染色 → L=34% |
| `--td-text-color-primary` | 主色色相、低饱和、L=20 → 保证 ≥7:1 | L=92 → 保证 ≥7:1 |
| `--td-text-color-secondary` | L=33 → 保证 ≥4.5:1 | L=76 → 保证 ≥4.5:1 |
| `--td-text-color-placeholder` | 保证 ≥3.0:1（页面底**和**容器底都要过） | 同左 |
| `--td-text-color-disabled` | 保证 ≥3.0:1（TDesign 的「暂无数据」也走这一档） | 同左 |
| `--td-text-color-brand` | 主色压暗到 ≥4.5:1（页面底 + 容器底都过） | 主色提亮到 ≥4.5:1 |
| `--td-chart-color-1..10` | 第 1 档 = 主色（不足 2.5:1 时自动压深一档），第 2 档 = 强调色，其余按主色色相 ±26°/±58°… 展开 | 同左（基于提亮后的主色） |

所有「保证 ≥N:1」都由 `ensureContrast(fg, bg, ratio)` 实现：**沿明度轴逐 1% 步进，返回最近的达标值**——即需求要求的「自动修正到最近达标值」，修正结果同时写进控制台告警与检查报告。

## 四、主色上的文字：两种模式的两种活法

TDesign 的 `--td-brand-color` 一变量两用：既是主按钮底色，又是链接/选中页签文字色。两种用法对明度要求相反，所以：

| | 亮色模式 | 深色模式 |
|---|---|---|
| 白字在主色上 ≥4.5？ | 否（8 套里 7 套不达标，仅深海蓝/墨莓浅色达标） | 否（8 套全不达标） |
| `--td-brand-color`（主交互面） | 下移到压暗版 `--app-brand-strong`（白字保持） | 保持**提亮后**的主色（作为文字/图标在深底上可辨） |
| 主色上的文字 | 白字（`--app-on-brand: #fff`） | 深色油墨（`--app-on-brand`，同色相 L≈12%） |
| 实测 | 4.53 ~ 6.42 | 4.52 ~ 4.74 |

`--app-brand-strong` 始终按「白字 4.5:1」推导，可直接用于任何小号白字场景：

```css
.my-badge { background: var(--app-brand-strong); color: #fff; }
```

`palette-bridge.less` 只把这两个 token 接到 TDesign 的**实心主按钮、实心标签、浅色标签、侧栏选中菜单项**上（禁用态主按钮改用占位文字色）。不改任何组件结构。

> ⚠ 桥接层里每个 `var()` 都必须带 fallback（`var(--app-on-brand, #ffffff)` / `var(--app-brand-on-tint, var(--td-brand-color))`）。
> 因为「用户不选方案」时这些变量根本不存在，裸写 `color: var(--app-on-brand)` 会命中 *invalid at computed-value time*，
> `color` 是继承属性 → 退化成继承父级颜色（Chromium 实测主按钮文字变 `rgb(51,51,51)`，在 `#0580a2` 上只有 2.78:1），
> 直接让「升级后界面不变」这条验收失守。

## 六、切换是怎么实现的

1. `usePalette.setPalette(id)` 更新模块级 `ref`（`null` 表示「跟随默认」）→ `applyPalette()`；
2. **`id === null`（默认态）**：不写任何变量，反而把上一次注入的变量逐条 `removeProperty`，并移除 `data-palette` / `data-palette-mode` 属性，同时 `localStorage.removeItem('cailu-palette')` —— 界面立刻回到 `theme.less` 原样；
3. 已选方案时：`buildPalette(id, mode)` 得到变量表，逐条 `document.documentElement.style.setProperty(name, value)`（**内联 style**），并在 `<html>` 上写 `data-palette="<id>"` 与 `data-palette-mode="light|dark"`（供 CSS 特例与自动化断言使用）；
4. `localStorage['cailu-palette'] = {"palette","mode","updatedAt"}` 持久化（**默认态不落盘**，所以「没选过」与「恢复默认」在存储上完全等价）；
5. 明暗自 `stores/setting.ts` 的 `themeMode` 单一控制，`initPalette()` 里 `watch(themeMode)` → 重算整套变量 —— 所以**换配色不丢明暗，换明暗不丢配色**；默认态下明暗行为与升级前一致（只切 `theme-mode`）；
6. `main.ts` 在 `app.mount()` 之前调用 `initTheme()` + `initPalette()`，首屏直接用最终配色（不会先闪一帧默认色再跳色）。

**为什么用内联 style 而不是注入 `<style>`**：TDesign 把品牌色写在 `:root[theme-mode='light'|'dark']`（特异性 0,1,1），`theme.less` 靠"同特异性 + 后加载"取胜；注入的 `<style>` 也是 0,1,1，一旦有第三方样式晚于我们加载就会被压回默认色。内联 style 在层叠中优先级最高，任何选择器都盖不掉，换肤结果与加载顺序无关。

**`theme.less` 保持原样**，既是默认态的唯一配色来源，也是 JS 未执行/异常时的兜底（不会白屏）。

**图表跟随**：`EChart.vue` 在 `setOption` 前统一注入 `color`（来自引擎推导的 10 档图表色）与坐标轴/图例的文字与线条色；配色版本号变化时重绘。**默认态下 `withPaletteTheme` 直接原样返回 option**，图表外观与升级前完全一致。业务页面写死的语义色（如"成功/失败"两条曲线）保持优先。

## 七、怎么新增一套方案

1. **加色板**：在 `palettes.ts` 的 `PALETTES` 末尾追加一条，并在 `PaletteId` 联合类型里加上新 id：

```ts
{
  id: 'ink-copper',            // 稳定 id，会写进 localStorage，定下就别改
  name: '墨青铜',
  note: '墨青 × 霜白 × 古铜',
  brand: '#3F6B6B',
  brandLight: '#9FC2C2',
  merge: '#F0F2F0',
  border: '#B3C4C4',
  accent: '#B08256',
}
```

2. **登记期望值**：在 `scripts/check-palettes.mjs` 的 `EXPECTED` 数组里加一行（防止以后误改色值），同时把 `PALETTES.length !== 8` 的断言改成 9、把文档/报告里的「8 套 / 16 组」同步成「9 套 / 18 组」。
3. **跑检查**：`pnpm check:palettes`。若有组合不达标，脚本会报出具体项与实测对比度；按提示调整新色板（**不要**去调阈值）。
4. 页面无需改动：设置页、顶栏快捷面板、导航都是遍历 `PALETTES` 渲染的。

## 八、已知限制

1. **方案 5 的浅色是推断值**（`#BFA5CB`，原稿 `#BFS5CB` 非法），待原稿确认。
2. **TDesign 语义色未跟随配色**：错误红 / 成功绿 / 警告橙仍是 TDesign 自带值（`--td-error-color` 等）。在深色模式浅色标签上实测约 2.8~3.5，**低于 AA**；这是改动前就存在的深色模式属性（用回退主题实测 3.74，本功能 3.44，差异来自底色更"有色"），本次为不影响危险按钮白字而未改动它们。后续可给语义色也加一层 `ensureContrast`。
3. **表头 / 面包屑 / descriptions 标签**用的是 `--td-text-color-placeholder`，实测 3.0~3.6（满足"占位 3.0"的约定，但达不到普通文字的 4.5）。这是 TDesign 的变量映射，不是配色引擎能单方面改的。
4. **工作台问候条的渐变**由配色生成（压暗主色 → 中段 → 强调色），白字在起点/中段已校验 ≥4.5；渐变末端的强调色属装饰区（无正文）。深色模式下如果浏览器把文字排到最右端，尾端对比度会偏低。
5. **跨设备不同步**：只存 localStorage。登录用户同步到后端偏好是 P1，接口占位在 `src/api/system/preference-api.ts`（未接入）。
6. **不支持"跟随系统"自动明暗**：当前是显式浅色/深色两档。
